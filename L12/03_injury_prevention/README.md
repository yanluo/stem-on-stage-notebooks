# Project 3 — Injury prevention

> **Detect hard landings, left/right asymmetry, and fatigue drift in dancer-mounted accelerometer data.**

## Ethical framing

This tool is **assistive, not diagnostic**. It surfaces patterns that might warrant a coach's attention. It does not diagnose injuries, and you should not tell anyone they're "injured" based on what this script outputs. Be careful and clear about that whenever you show this to non-engineers.

## What's in here

- [`injury_starter.ipynb`](injury_starter.ipynb) — load 3 minutes of jumps → peak detection → impact histogram → fatigue trend → asymmetry comparison.
- [`../../data/sample-landings.csv`](../../data/sample-landings.csv) — 180 s of synthetic landings, last minute simulates fatigue.
- [`../../data/sample-landings-asymmetric.csv`](../../data/sample-landings-asymmetric.csv) — per-jump left/right magnitudes (right is consistently heavier).
- Both generated by [`generate_sample_landings.py`](../../data/generate_sample_landings.py).

## What you need

- 1× micro:bit v2 + battery + ankle strap (analytics from one ankle works for the histogram + fatigue plots).
- 2× micro:bit v2 if you want to do the asymmetry analysis on real data — one per ankle.
- A laptop with Colab access.

**No new device code is needed for this project.** Reuse the L11 datalogger — see the next section.

## Capturing your own data (no new wearable code)

This project's wearable is just **L11's datalogger**, mounted on an ankle instead of a wrist. The CSV format is identical (`t, x, y, z`), and the notebook computes magnitude in the load step.

End-to-end workflow:

1. Flash [`L11/wearable_datalogger.py`](../../L11/wearable_datalogger.py) to a v2 micro:bit. *(Already in the repo — same file the L11 lecture used.)*
2. Strap the board to the dancer's ankle (lateral side, near the malleolus — that's where the landing impact reads cleanly). For asymmetry analysis, flash and mount a second board to the other ankle.
3. Press **A** on the board to start logging, do a few minutes of jumps, press **B** to stop.
4. Plug the board into a laptop, open `MICROBIT/MY_DATA.HTM`, click **Download** to save a CSV.
5. In the starter notebook, swap the bundled `sample-landings.csv` path for your CSV. Everything else runs unchanged.

For the **two-ankle** case, both boards run the same L11 program. They don't need to be time-synced precisely — you're matching peak heights per board, not aligning waveforms sample-by-sample.

The first project that actually needs new device code is the L13 *real-time alert* extension (lantern flashes red on a hard landing) — see the next section.

## What to build next (pick one as your L13 goal)

1. **Personal threshold.** Replace the global `height=1500` with `1.3 × median(first 30 landings)` for *this* dancer.
2. **Real-time alert.** MakeCode Python program that flashes the lantern red on a landing above the personal threshold.
3. **Multi-axis impact.** Sideways landings hide in `range_x` / `range_y`, not `mag`. Build a richer per-landing record.
4. **Rehearsal report.** matplotlib → PDF: histogram + fatigue fit + asymmetry, one page, dated. Coach reads it across weeks.
5. **Ground-truth check.** Coach calls out hard landings during capture; compare the script's flags to the coach's calls.

## Pitfalls and tuning notes

- **`height=` and `distance=`** in `find_peaks` are sensitive. The defaults in the starter (1500 mg, 1 s) are tuned to the bundled CSV. On real data you'll need to re-tune — start by looking at the magnitude plot and picking a height *below* every real landing but above the noise.
- **Asymmetry isn't always pathological.** Most people are mildly asymmetric. The signal you care about is *change* — a dancer who's normally symmetric and suddenly isn't.
- **A 3-minute recording is short.** Real fatigue effects show across a 90-minute rehearsal. Plan capture sessions accordingly.
